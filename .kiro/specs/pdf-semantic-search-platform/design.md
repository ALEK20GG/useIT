# Design Document

## pdf-semantic-search-platform

---

## Overview

This design covers a set of bug fixes and feature enhancements for the **UseIt** application — a SvelteKit 5 frontend paired with a FastAPI backend and an embedded (or Docker-hosted) Qdrant vector database. The corpus is a collection of up to 100 Raspberry Pi magazine PDFs stored under `frontend/static/pdf-source/`.

The work is split into two tracks:

- **Bug fixes (Requirements 1–6)**: Correct existing defects that prevent the application from working reliably — a typo in `requirements.txt`, collection recreation on every ingest, broken tab active-state, variable shadowing, a `NameError` in search, and deprecated Qdrant API calls.
- **Feature enhancements (Requirements 7–19)**: Add configurable CORS/backend URL, per-chunk page numbers, PDF deletion, indexed-PDF listing, search highlighting, filename filtering, single-PDF re-indexing, a health-check indicator, improved chunking, mobile responsiveness, dark mode, and paginated results.

The system remains a local-first application: no cloud services are required. All embeddings are generated by the `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` model running in-process.

### Key Architectural Decisions

1. **No separate research/notes files** — all design findings are embedded here.
2. **Qdrant payload as source of truth for metadata** — page numbers, `indexed_at`, `chunk_count` are stored in point payloads; no separate database is needed.
3. **Deterministic UUIDs** — chunk IDs are derived from `uuid5(namespace, f"{filename}:{chunk_idx}")` so re-indexing is idempotent.
4. **SvelteKit `$env/static/public`** — the `PUBLIC_BACKEND_URL` variable is inlined at build time, keeping the frontend a pure static bundle.
5. **CSS custom properties for theming** — a single `:root` block with `@media (prefers-color-scheme: dark)` override covers all pages without a JS theme toggle.

#### `pdf_utils.py` — Chunking (Requirement 16)

The `chunk_text` function is rewritten with a priority order:

1. Split at `\n\n` (paragraph boundary) within the last 200 chars of the window.
2. Fall back to sentence boundary (`.`, `!`, `?`) within the last 200 chars.
3. Fall back to nearest whitespace.
4. Hard split if no whitespace found.
5. Discard chunks shorter than 100 characters (merge into previous chunk) except for the final chunk.

Per-page extraction is added to `extract_text_from_pdf` so that each page's text is tagged with its 1-based page number before chunking.

#### `embeddings.py`

No changes required. The model is already cached via `@lru_cache`.

### Qdrant Point Payload Schema

Each chunk stored in the `pdfs` collection carries this payload:

```json
{
  "filename": "raspberrypi_issue_1.pdf",
  "file_path": "/absolute/path/to/file.pdf",
  "relative_url": "/pdf-source/raspberrypi_issue_1.pdf",
  "chunk_index": 0,
  "chunk_text": "...up to 500 chars...",
  "total_chunks": 42,
  "page_number": 3,
  "indexed_at": "2025-01-15T10:30:00Z"
}
```

`page_number` and `indexed_at` are new fields added by Requirements 9 and 11.

### Per-page Text Extraction

`extract_text_from_pdf` is updated to return a list of `(page_number: int, text: str)` tuples. The caller in `upload_pdf` / `index_all_pdfs` iterates over pages and calls `chunk_text` per page, tagging each resulting chunk with its source page number.

## Correctness Properties

*A property is a characteristic or behavior that should hold true across all valid executions of a system — essentially, a formal statement about what the system should do. Properties serve as the bridge between human-readable specifications and machine-verifiable correctness guarantees.*

### Property 1: Chunk round-trip completeness

*For any* non-empty input text, the set of words produced by concatenating all chunks returned by `chunk_text` SHALL be a superset of the set of words in the original text (every word is preserved across the chunked output).

**Validates: Requirements 16.4**

### Property 2: Chunk minimum length invariant

*For any* non-empty input text longer than 100 characters, every chunk produced by `chunk_text` except the last SHALL have a length of at least 100 characters.

**Validates: Requirements 16.3**

### Property 3: Keyword boost is bounded

*For any* query string and chunk text, the value returned by `calculate_keyword_boost` SHALL be in the closed interval `[0.0, 0.3]`.

**Validates: Requirements 5.1, 5.2**

### Property 4: Normalized score is bounded

*For any* raw cosine similarity score in `[-1.0, 1.0]`, the value returned by `normalize_cosine_score` SHALL be in the closed interval `[0.0, 1.0]`.

**Validates: Requirements 5.1**

### Property 5: Filename filter exclusion

*For any* search response with a non-null `filename_filter`, every `PDFSearchResult` in the results list SHALL have a `filename` that contains the filter string (case-insensitive).

**Validates: Requirements 13.2**

### Property 6: Pagination offset correctness

*For any* search query and total result set of size N, the results returned with `offset=k` and `limit=L` SHALL be identical to taking the full result list sorted by score and slicing `[k : k+L]`.

**Validates: Requirements 19.2**

### Property 7: Ingest is additive (no data loss)

*For any* Notes_Collection that already contains M points, calling `/semantic/ingest` with K new notes SHALL result in the collection containing at least M points (existing points are not deleted).

**Validates: Requirements 2.1, 2.2**

### Property 8: Preview text sanitization safety

*For any* `preview_text` string containing HTML special characters (`<`, `>`, `&`, `"`), the sanitized output used in `{@html ...}` SHALL not contain unescaped `<script` or `<iframe` substrings.

**Validates: Requirements 12.4**

### Property 9: ARIA accessibility compliance

*For any* interactive element with click handlers, the rendered DOM SHALL include appropriate ARIA roles, keyboard event handlers, and descriptive labels for screen reader compatibility.

**Validates: Requirements 20.1, 20.2, 20.3, 21.1, 21.2, 21.4**

### Property 10: Color contrast compliance

*For any* color combination used in the design system, the contrast ratio SHALL meet or exceed WCAG AA guidelines (4.5:1 for normal text, 3:1 for large text) in both light and dark modes.

**Validates: Requirements 18.3, 23.1**

## Error Handling

### Backend

| Scenario | HTTP Status | Behaviour |
|----------|-------------|-----------|
| Upload non-PDF file | 400 | `detail: "File must be a PDF"` |
| PDF with no extractable text | 400 | `detail: "PDF contains no extractable text"` |
| `DELETE /pdf/{filename}` — not found | 404 | `detail: "No indexed points or file found for '{filename}'"` |
| `POST /pdf/reindex/{filename}` — file not on disk | 404 | `detail: "File not found in pdf-source: '{filename}'"` |
| `delete_collection` on non-existent collection | — | Exception caught; proceed to `create_collection` silently |
| Qdrant unreachable on `/health` | 503 | `detail: "Unable to reach Qdrant: ..."` |
| Embedding model failure | 500 | `detail: "Failed to generate embeddings"` |
| General unhandled exception | 500 | `detail: "Error processing PDF: ..."` |

### Frontend

- All `fetch` calls are wrapped in `try/catch`; errors are displayed in a `.status.error` paragraph.
- The health indicator uses `AbortController` with a 5-second timeout; a `TypeError` (network failure) or timeout sets status to "Offline".
- The delete button is disabled while a delete request is in flight to prevent double-clicks.
- Pagination buttons are disabled when on the first/last page respectively.
- `{@html highlightedText}` is only used after sanitizing `preview_text` through a `sanitizeHtml` helper that escapes `<`, `>`, `&`, `"` before wrapping query terms in `<mark>` tags.
- **Accessibility error handling**: Screen readers receive appropriate error announcements via `aria-live` regions
- **Visual design error states**: Error messages use semantic color tokens and maintain proper contrast ratios
- **Keyboard navigation errors**: Focus management ensures users can navigate away from error states using keyboard

## Testing Strategy

### Unit Tests (Python — `pytest`)

Focus areas:
- `chunk_text`: boundary conditions (text shorter than chunk size, text with no paragraph breaks, text with only whitespace).
- `clean_extracted_text`: normalization of multiple spaces and newlines.
- `calculate_keyword_boost`: zero query words, all words match, no words match.
- `normalize_cosine_score`: boundary values `-1.0`, `0.0`, `1.0`.
- `sanitizeHtml` (TypeScript, Vitest): XSS payloads, normal text, empty string.

### Property-Based Tests (Python — `hypothesis`)

Each property test runs a minimum of 100 iterations. Tests are tagged with a comment referencing the design property.

```python
# Feature: pdf-semantic-search-platform, Property 1: chunk round-trip completeness
@given(st.text(min_size=1, max_size=5000))
@settings(max_examples=100)
def test_chunk_roundtrip(text): ...

# Feature: pdf-semantic-search-platform, Property 2: chunk minimum length invariant
@given(st.text(min_size=101, max_size=5000))
@settings(max_examples=100)
def test_chunk_min_length(text): ...

# Feature: pdf-semantic-search-platform, Property 3: keyword boost bounded
@given(st.text(), st.text())
@settings(max_examples=100)
def test_keyword_boost_bounded(query, chunk): ...

# Feature: pdf-semantic-search-platform, Property 4: normalized score bounded
@given(st.floats(min_value=-1.0, max_value=1.0, allow_nan=False))
@settings(max_examples=100)
def test_normalize_score_bounded(score): ...
```

Properties 5–10 require integration-level setup (Qdrant, frontend rendering) and are covered by integration tests with representative examples rather than full property-based tests.

### Integration Tests

- `POST /pdf/upload` → verify Qdrant contains expected chunk count and `page_number` payload.
- `POST /pdf/index-all` → verify idempotency (running twice does not duplicate points).
- `DELETE /pdf/{filename}` → verify points removed and file deleted.
- `GET /pdf/list` → verify `chunk_count` and `indexed_at` fields are present.
- `POST /semantic/ingest` (twice) → verify point count is additive.

### Frontend Tests (Vitest + Svelte Testing Library)

- Tab active-state: clicking "Cerca PDF" applies `active` class to correct button.
- Health indicator: mock `fetch` returning 200 → green dot; mock network error → red dot.
- Pagination buttons: disabled state on first/last page.
- `sanitizeHtml`: XSS payloads are neutralized; query terms are wrapped in `<mark>`.
- **Accessibility tests (Requirements 20-22)**: 
  - Drag-drop areas have `role="button"`, `tabindex="0"`, and `aria-label`
  - Clickable divs have keyboard handlers and proper ARIA roles
  - PDF iframe has descriptive `title` attribute
- **Visual design tests (Requirement 23)**:
  - CSS custom properties have correct values
  - Contrast ratios meet WCAG AA guidelines
  - Interactive elements have proper hover/focus/active states
  - Animations respect `prefers-reduced-motion`

**Collezione "pdfs":**
- Vettori dei chunk di testo estratti dai PDF

**Collezione "notes":**
